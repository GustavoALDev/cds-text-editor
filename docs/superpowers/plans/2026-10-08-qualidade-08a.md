## Armadilhas conhecidas (resumo)

- Cache do Nx devolve artefato da versão do *lockfile*: pernas sem cache (`NX_SKIP_NX_CACHE=true`); o `--no-save` não muda o lockfile.
- `npm install --no-save` do Angular último pode conflitar com `@nx/angular` 23.2.1: o spike decide; plano B = Angular último só pela fase A (consumidor).
- `next` pode ser o *major* 23 (fora do peer `<23`): só fase A, `--legacy-peer-deps`, `continue-on-error`.
- "Último" muda no meio do dia: tetos versionados com `reason` e `adr`; o semanal pega antes; nunca esconder.
- A fase A deve empacotar com a cadeia da raiz (é o que se publica): não deixar o `npm install --no-save` da fase B contaminar o `pack`.
- Nome do check do PR deve ser exatamente `compat (latest×latest)` (o `branch-protection.json` e seu teste dependem disso).
- J8 diverge entre motores por cookie de CSRF/`SameSite` em `127.0.0.1`: registrar a causa, não `skip`.
- Plano B do tema divergente entre motores: corrigir CSS e TS juntos (regra do `CLAUDE.md`).
- Proteção de branch só com confirmação explícita do usuário; sem permissão, `TODO-AUTOR` com o comando.
- Junção de `node_modules` entre worktrees: nada de `npm ci`/`npm install` na raiz; npm 10 local: `npx -y npm@11`; `TMPDIR` pequeno: `RTE_CONSUMER_DIR` em disco; nunca `python -`.
