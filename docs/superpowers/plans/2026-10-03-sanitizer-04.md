# Spec 04 — Sanitizador (`@cds/rte-sanitizer`): plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar `sanitizeRichText`/`createSanitizer`: uma engine própria, pura e sem DOM sobre o `Parser` do `htmlparser2` ^12, que devolve só o que o esquema do core aceita, na forma canônica do editor, igual em Node e nos 3 navegadores. Junto vêm os interpretadores de S4 no entry `.` do core.

**Architecture:** São três passadas sobre uma árvore leve própria, todas sem recursão nativa. (1) `parseHtml`: o `htmlparser2` monta a árvore crua. Os atributos vêm por `onattribute`, a profundidade é conferida a cada abertura e o conteúdo de S3b é descartado já aqui. (2) `sanitizeTree`: percurso com contexto de saída (pai, dentro de `p`, dentro de `a`). Aplica S3a/S3c, `getElementSpec` e `sanitizeAttributes` na entrada; os filhos; na saída, `hasRequiredChild` (S6). Depois vem uma pré-ordem de S7. (3) `serializeNodes` (S13) com os `escape*` do core. Toda regra do que é aceito vem dos interpretadores do core (R1). As listas de `parser-model.ts` descrevem só o parser HTML.

**Tech Stack:** TypeScript 6, `htmlparser2` 12.0.0 (já no lockfile), Vitest 4 (`node`), fast-check 4.10.2, `@vitest/coverage-v8` ~4.1, Playwright (Chromium, Firefox, WebKit), esbuild (bundle E2E e orçamento), tsup.

**Spec:** `docs/specs/04-sanitizador.md` é vinculante e deve ser lida inteira antes de qualquer tarefa: §3 traz S1–S14, §4 a API exata e §6 os testes. Contexto: `docs/decisions/0003-esquema-do-html.md` ("Pendências conhecidas", decisão 16) e `docs/decisions/0004-extensoes-de-conteudo.md` (B4, B18, B20).

## Global Constraints

- **Engine (S1):** só o `Parser` do `htmlparser2` com `{ decodeEntities: true }`; as outras opções ficam no padrão HTML (`lowerCaseTags`, `lowerCaseAttributeNames`, `recognizeSelfClosing: false`). Nada de `sanitize-html` nem de `DOMPurify`. **Nenhum pacote novo no lockfile**; `npm run check:licenses` e `npm run notices` sem diff.
- **Dependências (S10):** `htmlparser2` `^12.0.0` em `dependencies`; `@cds/rte-core` `0.0.0` em `peerDependencies`. Não reexportar `htmlToText`, `countWords` nem `readingTime`.
- **Imports (R12):** o código do sanitizador importa só `@cds/rte-core` (entry `.`) e `htmlparser2`. Os testes podem usar `@cds/rte-core/html`. Nada de `@angular/*`, `@tiptap/*` nem `@cds/rte-core/*`. As tags `scope:*` não mudam.
- **R1:** o sanitizador não tem allowlist própria. Toda busca no esquema passa por `getElementSpec`/`Object.hasOwn`, e tags e atributos de entrada vão para `Map`/`Set`, nunca para chave de objeto.
- **R9:** nenhum acesso a `window`/`document`/`navigator`, nem no topo nem na execução; só o global `URL` (via `isAllowedUrl`). O sanitizador padrão é criado de forma preguiçosa, na primeira chamada.
- **Limites (S8):** `maxInputLength` padrão `1_000_000` (unidades UTF-16) e `maxDepth` padrão `256`. Uma opção que não é inteiro ≥ 1 lança `RangeError`; uma entrada que não é `string` lança `TypeError`. A profundidade estoura quando `depth + 1 > maxDepth`, como no `walk.ts` (256 aninhados passam, 257 lançam), e a conta inclui elementos dentro de conteúdo descartado.
- **Serialização (S13):** o texto escapa `& nbsp < >`; os atributos escapam `& nbsp " < >`, sempre entre aspas duplas; CR/CRLF → LF; NUL → U+FFFD; booleanos saem `nome=""`; void (`br`, `hr`, `img`, `input`, `col`, `track`…) sai sem fechamento; comentário, *doctype*, PI e CDATA nunca saem.
- **Sem recursão nativa** em `parseHtml`, `sanitizeTree`, `dedupeIds` e `serializeNodes` (pilha explícita; Review Focus 3).
- **Tamanho (S12):** orçamento = `Math.ceil(medido * 1.15 / 64) * 64`. Teto de reavaliação: **40 960 B** min+gzip no cenário `whole`. Acima dele, parar e reportar (S14) em vez de subir o orçamento.
- **Propriedades:** semente padrão `20261003`; `FC_SEED`/`FC_RUNS` respeitados; **≥ 10 000** execuções em R3, R4 e R5.
- **Fixtures:** leitura com `\r\n?` → `\n` (checkout com `autocrlf`), como o `readFixture` do core; a escrita grava exatamente o texto (`UPDATE_FIXTURES=1`).
- Código e nomes públicos em inglês; comentários, mensagens de erro e documentação em pt-BR.
- **Windows:** `export NX_DAEMON=false`; `npx prettier --check --end-of-line auto <arquivos>` antes de cada commit; Playwright sempre com `--workers=4`.
- Antes de cada commit: `npx nx run-many -t lint,typecheck,test -p core,sanitizer` verde.
- Commits em pt-BR (`feat(sanitizer): …`, `feat(core): …`), terminando com a linha `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Branch: `feat/spec-04`.

## Review Focus

1. **Bloco dentro de `p` por um elemento desembrulhado** (`<p><span><ul><li>x</li></ul></span></p>`, `<p><font><table>…`). O `htmlparser2` só fecha o `p` quando o bloco é filho direto, mas o navegador fecha o `p` "em escopo de botão" e reestrutura a saída, quebrando I1. O esperado é uma saída estável. Teste na Tarefa 3.
2. **`pre` com LF inicial** (`<pre>\n\nx</pre>`, `<pre><x></x>\nx</pre>`). O navegador descarta o 1º LF depois de `<pre>`, e a releitura muda o texto. O esperado é a saída sem LF inicial e idempotente. Teste na Tarefa 3.
3. **`maxDepth` alto com entrada profunda** (`createSanitizer({ maxDepth: 20_000 })('<b>'.repeat(20_000) + 'x')`). Com recursão nativa, a pilha estoura (`RangeError: Maximum call stack size exceeded`). O esperado é terminar em < 2 s com o texto preservado. Teste na Tarefa 4.
4. **Objeto de opções do editor passado direto ao sanitizador** (S9/B18: `codeLanguages`, `placeholder`, `charLimit`, `slash`… junto de `features`). O esperado é aceitar, ignorar o que não é do esquema e dar a mesma saída que só as chaves de `RteHtmlSchemaOptions`. Teste na Tarefa 4.
5. **`id` de um elemento removido depois** (`<figure><h2 id="rt-a">a</h2></figure><h2 id="rt-a">b</h2>`). Com S7 aplicado durante a leitura, o `id` sobrevivente some. O esperado é que só elementos que ficam na saída contem para "primeira ocorrência". Teste na Tarefa 3.

## Pré-voo: conflitos entre a spec e o código (decididos pela spec)

1. O `tsconfig.base.json` não tem o alias `@cds/rte-core/html`, que R12 permite nos testes. A Tarefa 2 acrescenta `"@cds/rte-core/html": ["./packages/core/html/src/index.ts"]`.
2. O `onopentag` do `htmlparser2` 12 entrega `attribs` num objeto literal. Lá `__proto__` se perde e repetidos são descartados. A árvore crua usa `onattribute` (todos, na ordem, como o `validateHtml`), e `sanitizeAttributes` aplica "primeiro vence" (S5).
3. Em S5, "inválido com `default` recebe o `default`" junto com "o que é acrescentado vai ao fim": o valor inválido sai da posição dele e o `default` é acrescentado ao fim, na ordem de `spec.attributes`. Para `ensureTokens`, o `rel` existente é reescrito **no lugar**; o `rel` ausente é acrescentado nessa mesma ordem, e o `style` de `styleFrom` vem por último.
4. S7 roda numa pré-ordem sobre a **árvore final**, depois de S6. Um elemento removido não consome o `id` (Review Focus 5).
5. Normalizações de S3c tiradas do algoritmo de leitura do HTML. A spec cita só tabela, `tr`→`tbody` e `a` em `a`. Cada uma ganha caso de regressão e linha no ADR 0006 (N1–N7, Tarefa 3):
   - P_CLOSING com ancestral `p` na saída → desembrulha;
   - `li` sem pai `ul`/`ol` → desembrulha;
   - título filho direto de título → desembrulha;
   - partes de tabela fora do pai (`caption`/`colgroup`/`thead`/`tbody` fora de `table`, `tr` fora de `table`/`thead`/`tbody`, `th`/`td` fora de `tr`, `col` fora de `colgroup`) → desembrulha, porque o navegador ignora essas tags fora da tabela;
   - `pre`: todos os CR/LF iniciais do 1º texto são removidos (nó vazio sai).
6. §6.3 pede CSP "sem `unsafe-inline`" **e** cores por `computedStyle`, mas um `style=""` vindo de `innerHTML` é bloqueado por `style-src`. A página usa `default-src 'none'; script-src 'self'; style-src 'self'; style-src-attr 'unsafe-inline'; img-src 'self'; media-src 'self'; frame-src 'self'`. Toda violação com `effectiveDirective` começando por `script-src` conta como XSS, porque o CSP não pode esconder um *handler* que vazou.
7. `dangerous-urls.ts` é um gerador, não uma lista, e o sanitizador não pode importar `testing/` do core (limite de projeto). Ele vira `fixtures/content/dangerous-urls.json` `{ "schemes", "noise", "examples" }`. Core e sanitizador montam o mesmo gerador a partir do JSON; o core mantém os exports `DANGEROUS_SCHEMES`/`dangerousUrl`.
8. Pendências da 03a (§8 da spec; ADR 0003, "Pendências conhecidas") ganham testes que falham hoje e são corrigidas no core na Tarefa 1:
   - `sanitizeStyle` descarta a declaração cujo valor tem `(` ou `@` (cobre `url(`, `image-set(`, `@import`);
   - `serializeTokens` separa por espaço **ASCII** (`/[ \t\n\r\f]+/`), como o HTML e o `hasUnknownToken` do `validateHtml`.
9. Os `escape*` iguais ao `getRteHtml`: `interpret.spec.ts` (entry `.`) confere os literais; a equivalência com o serializador fica coberta pelo `string-dom.spec.ts`, que continua verde depois de o `string-dom.ts` passar a importá-los.
10. R10 "fixture repetido" repete `id`s, e S7 os remove; o número de R10 é só tempo, sem comparar saída.
11. A cobertura ≥ 95% fica como `thresholds` no `vitest.config.mts` do sanitizador, conferida com `--coverage` na Tarefa 9 (fora do alvo `test` do CI, por tempo).
12. `npm run check:size` roda só `theme:size`. O sanitizador ganha o alvo `size` e é conferido por `npx nx run sanitizer:size`; o CI já roda `nx affected -t size`.
13. Os bytes de referência do Node em R6 são calculados no processo do Playwright, importando `packages/sanitizer/src/index.ts`.

```text
para cada nó cru, no contexto ctx:
  texto            → acrescenta [T3: descarta se ctx.parent ∈ TABLE_CONTENT]

  r.remove         → descarta com o conteúdo
  r.unwrap         → desembrulha
  [T3: regras de contexto N1–N5 → desembrulha; filho fora de TABLE_CONTENT(ctx.parent) → descarta]
  el = { tag, attributes: r.attributes, children: tag === 'iframe' ? [] : filhos em ctx' }
       ctx' = { parent: tag, inP: ctx.inP || tag === 'p', inA: ctx.inA || tag === 'a' }
  [T3: pós — pre (N6), table/tbody (N7), hasRequiredChild (S6)]
  acrescenta el
[T3: depois de tudo, dedupeIds (S7)]
```
