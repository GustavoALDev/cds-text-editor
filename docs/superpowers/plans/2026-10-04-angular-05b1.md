# Angular 05b1 — Barra de ferramentas, tema por instância e CSS de conteúdo (`@cds/rte-angular`, `@cds/rte-core`): plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dar ao `rte-editor` a barra de ferramentas acessível (APG *toolbar* + *menu button*, `popover` nativo, ícones Lucide incorporados, estado por transação sem re-render, todos os comandos sem diálogo, guarda de tabela > 100), o tema por instância por `applyRteTheme` compatível com a CSP, o `content.css` `rt-*` no `@cds/rte-core` e a correção do `blur` — provados em jsdom (zoneless e zone.js) e nos 3 motores do Playwright.

**Architecture:** O core ganha um arquivo CSS exportado (`styles/content.css`, camada `rte.content`) e o `editor.css` fica só com o funcional. No Angular, a barra é um componente **interno** (`RteToolbar`) renderizado pelo template do `RteEditor` como primeiro filho de `.rte-editor__frame`; um modelo puro (itens, presets, resolução de grupos, estado por item, comandos, ensaio da guarda) vive em `src/toolbar/*.ts` e duas diretivas internas (`RteRovingFocus`, `RteMenu`/`RteMenuTrigger`) implementam os padrões APG. O estado lê a versão da ponte da 05a num `computed` por transação, e cada item recebe um `Signal` estável com igualdade por campos. O tema é mesclado por chave (instância > *provider*) e aplicado no host com `applyRteTheme` num `afterRenderEffect`; o `blur` de `disabled`/`hidden` passa para `afterRenderEffect`.

**Tech Stack:** Angular 22.2.1 (`afterRenderEffect`, signals, OnPush, zoneless/zone.js), Tiptap 3.31.4 (`@tiptap/pm/tables` para o ensaio), `@cds/rte-theme` (`applyRteTheme`, `warnIfPoorTheme`), Popover API nativa, Vitest 4.1 + jsdom pelo *builder* `unit-test` (`test`/`test-zone`), fast-check 4.10, postcss (leitura de CSS nos testes), Playwright 1.63 (3 motores) + `@axe-core/playwright`, ícones Lucide (ISC) copiados como dados.

**Spec:** `docs/specs/05b1-barra-de-ferramentas-e-tema.md` (vinculante; ler inteira antes de qualquer tarefa — §3 tem U1–U20, §4 a API e a tabela de itens, §5 R1–R17, §6 os testes). Contexto: `docs/specs/05-editor-angular.md`, `docs/specs/05a-componente-e-formularios.md`, ADR 0007 (rulings 10 e 28; pendências do componente), ADR 0002 (tema), ADR 0004 (tabelas, decisões 33–34), ADR 0005 (ruling 5).

## Global Constraints

- Sem `@angular/aria`, sem `@angular/cdk`, sem `lucide-angular`, sem biblioteca de posicionamento; nenhuma dependência de produção nova (`npm run check:licenses` inalterado).
- Grafo: `scope:angular` → `['scope:core', 'scope:theme']`; `scope:e2e` → `['scope:angular', 'scope:core', 'scope:theme']`. `@cds/rte-theme` sai de `ignoredDependencies` (agora importado). Nada importa `@cds/rte-sanitizer`; o entry `.` continua sem `@cds/rte-core/html`.
- **CSP:** nenhum `[style…]`/`[ngStyle]`/`[style.x]` em template ou em `host`; estilo em tempo de execução só por CSSOM (`style.setProperty`), feito por `applyRteTheme` e pelo posicionamento do menu. Ícones por atributos SVG (`[attr.d]`), amostras de cor por classe.

## Pré-voo: conflitos entre a spec e o código (decididos pela spec)

1. **Empacotamento do `content.css` (R1).** O core é tsup e o `check-pack` só aceita `dist/` em pacotes tsup. Pela spec: fonte e arquivo publicado em `packages/core/styles/content.css` (sem cópia para `dist`), `exports["./styles/content.css"]: "./styles/content.css"`, `files` + `"styles"`, `sideEffects: ["**/*.css"]` (troca o `false`); `tools/check-pack.mjs` passa a aceitar `/^styles\/[^/]+\.css$/` também em `TSUP_OUTPUT` (caso novo em `check-pack.test.mjs`). O `nonCodeEntrypoints` já tira o CSS do attw.
2. **Seletores repetidos e "só o funcional" no `editor.css` (R11).** Hoje o `editor.css` tem `.rte-content` (raiz), `.rte-content pre`, `table`, `td, th`, `.rt-tasks`, `.rt-task`, `.rt-figure`, `.rt-figure img`. Decisão: vão para o `content.css` a aparência (bordas de célula, `border-collapse`, fundo/cor/fonte/raio do `pre`, lista sem marcador das tarefas, `width: fit-content`/`max-width` da figura e o `img` responsivo); no `editor.css` as regras de edição que colidiriam passam a `.rte-editor .rte-content …` (raiz com `padding`/`min-height`/`white-space`; `pre { white-space: pre-wrap }`; `table { table-layout: fixed }`; `td, th { position: relative; min-width: 1em }`; `.rt-figure { position: relative }`; `.rt-task { display: flex; … }` da vista de tarefa). Regra de teste: regra do `editor.css` cujo seletor cita `.rt-*`, `table`, `td`, `th` ou `pre` só declara propriedades de `FUNCTIONAL_PROPS = ['position','white-space','table-layout','min-width','cursor','user-select','pointer-events','touch-action','z-index','box-sizing','display','align-items','gap','flex','overflow-x']`. `hljs-*` fica no `editor.css` (decorações só existem no editor; o realce publicado é decisão da spec 06).
3. **Cobertura de classes (R11).** "Todo `rt-*` do esquema com todos os recursos" = `classes.values` de `getHtmlSchema({ features: { colors, code, tables, tasks, media, embeds, newsBlocks: true }, embedProviders: <provedores embutidos de @cds/rte-core/embeds> })` (inclui `rt-embed--youtube|vimeo|spotify`); padrões abertos (`^language-…$`) ficam fora.
4. **Página estática `content-static` (§6.2).** Uma rota Angular com `[innerHTML]` passaria pelo sanitizador do Angular (remove `style`, `iframe`) e o *prerender* exigiria copiar o fixture. Decisão: `e2e/angular/serve.mjs` responde `GET /content-static` montando, em memória, `<!doctype html>` + `<link rel="stylesheet">` para `/__static/theme.css` e `/__static/content.css` (servidos de `packages/theme/src/theme.css` e `packages/core/styles/content.css`) + `<div class="rte-root"><div class="rte-content">` + `fixtures/content/all-features.html`, com a mesma CSP. Os atributos `style` do fixture ficam bloqueados — é o cenário da R12.
5. **Exclusões da R12.** A cláusula "o que vem do atributo `style` bloqueado pela CSP" cobre também `aspect-ratio` dos *embeds*, além de `text-align` e larguras de coluna; as tarefas comparam só o `li.rt-task` (DOM interno da vista do editor difere: `rte-task__*` × `label > input`). Registrado no ADR 0008 e como consequência para a spec 06.
6. **`Shift+Tab` do editável agora para na barra (U2).** O N6 da 05a ("`Tab`/`Shift+Tab` saem do editor a partir de um parágrafo") passa a: `Shift+Tab` foca o item ativo da barra, um segundo `Shift+Tab` sai do editor; tabela: `Shift+Tab` na primeira célula vai à barra. O N2 (`disabled` pula o editor) continua valendo porque os botões ficam `disabled` nativos (U10). A barra `'article'` aparece em todas as páginas e testes existentes; testes que contam paradas de foco são ajustados, nenhum outro.
7. **Recursos antes da criação (U8, U10).** Para a barra sair igual no SSR, na casca e depois da criação, o *gating* lê `getHtmlSchema(...)` (do `@cds/rte-core`) sobre a configuração mesclada: antes da criação, `mergeEditorConfig(RTE_CONFIG.editor, options())` ao vivo; depois, a fixada na criação (`optionsAtCreation`). Opção inválida (que faria `getHtmlSchema` lançar) cai em `getHtmlSchema({})`. `codeLanguages` vem da mesma configuração. A paleta da U13 é `schema.palette`.
8. **Espiões de ESM.** Não dá para espiar `applyRteTheme` (namespace ESM do *bundle* de teste). O `theme.spec.ts` confere o efeito real no DOM do jsdom (sem `CSS.supports` o tema cai no plano B e grava `--rte-*` e `color-scheme` por `style.setProperty`; o *cleanup* os remove). `warnIfPoorTheme` é observado por espião de `console.warn` (mensagens `[rte-theme]`). Se o plano B não funcionar no jsdom, criar um token interno `RTE_THEME_APPLY` só para o teste e registrar no ADR.
9. **`ngDevMode` × `isDevMode()`.** A spec pede `ngDevMode` só para o `warnIfPoorTheme` (o import some em produção); os avisos de configuração da barra seguem a convenção da 05a (`isDevMode()`). O teste de "só em desenvolvimento" troca `globalThis.ngDevMode` para `false` e restaura.
10. **`data-rte-mode` em dois lugares.** A ligação de *host* (`[attr.data-rte-mode]`, sai no SSR) e o `applyRteTheme` (que também grava e, no *cleanup*, remove o atributo) escrevem o mesmo valor; a ordem detecção → `afterRenderEffect` (limpeza anterior, depois aplicação) mantém o atributo coerente. Nenhum `[style…]`.
11. **Direção (U3, U7).** `rtl` = `element.closest('[dir]')?.getAttribute('dir') === 'rtl'` (determinístico no jsdom); direção só por CSS sem atributo `dir` não é detectada — documentado no README.
12. **Alinhamento sem atributo.** `textAlign` `null` → nenhum `menuitemradio` marcado e o botão mostra o ícone `alignLeft`.
13. **Guarda (U14) no Angular**, em `src/toolbar/table-guard.ts`, ensaiando os comandos do `@tiptap/pm/tables` (`addRowBefore/After`, `addColumnBefore/After`, `mergeCells`) com `dispatch` que só captura a transação; o teste de propriedade compara com o comando do Tiptap aplicado de verdade numa **segunda** instância (caminho independente). Spans pré-existentes > 100 (API direta, ADR 0004) também bloqueiam.
14. **Ícones (U12).** Lucide numa versão fixada (`npm view lucide-static version` no dia; anotar), baixado com `npm pack lucide-static@<v>` em `$TMPDIR` (não vira dependência); elementos não-`path` (`rect`, `circle`, `line`, `polyline`) convertidos em `d` equivalente (modificação permitida pela ISC, citada no cabeçalho).
15. **Avisos de terceiros (R17).** `tools/generate-notices.mjs` só lista `dependencies`. Ganha a seção "Código incorporado" a partir de `tools/third-party-embedded.json` (`[{ name, version, license, source, files, licenseText }]`), também quando não há dependências de produção; `generate-notices.test.mjs` cobre os dois casos.
16. **Cache do app de teste.** `inputs` de `build`/`build-zone` do `angular-e2e-app` ganham `{workspaceRoot}/packages/core/styles/content.css`; `styles` na ordem `theme.css` → `content.css` → `editor.css` → `styles.css`.
17. **N15 × N8.** O custo por tecla com a barra `full` é medido na mesma rodada também com `toolbar: false` (comparação direta), além de citado contra o N8 do ADR 0007.
