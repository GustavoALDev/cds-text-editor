# Spec 07b — App de demonstração, playground do tema e consumo por tarball

> Parte 2 de 4 da spec 07 (07a, **07b**, 07c, 07d) (ver `07-demo-docs-exemplos.md`). Depende da spec 05 inteira (fechada no ADR 0016), da 06 (`@cds/rte-render`) e da 07a (`examples/server-node`, concluída). Entrega o §3.1 da spec 07 e a parte do R2 e dos critérios que cabem ao demo. Consumida pela 07c/07d (diretrizes Y1–Y12 no Apêndice A).
> Decisões tomadas por revisão técnica sob a diretriz do autor "o recomendado e mais seguro". Spec enxuta: só decisões que mudam comportamento, API ou processo. Fatos conferidos em 2026-10-07 (só leitura, nada executado nesta escrita): `apps/demo` é um *placeholder* (só `README.md`); o app de teste `e2e/angular/app` consome os pacotes **pelo fonte** (alias de `tsconfig.base.json` e `styles` apontando para `packages/*/…css`), é pré-renderizado (`outputMode: 'static'`, `RenderMode.Prerender` em `**`), hidrata com `withNoIncrementalHydration()` e `inlineCritical: false`, e é servido por `e2e/angular/serve.mjs` com a CSP `default-src 'self'; script-src 'self'; style-src 'self'` **por cabeçalho**; os *workspaces* do npm são só `packages/*`; os peers entre pacotes são exatos (`@cds/rte-core: 0.0.0`); versões exatas na raiz: Angular 22.2.1, Tiptap 3.31.4, TypeScript 6.0.3, `@microsoft/api-extractor` 7.59.4 (sem `docModel`); `tools/check-pack.mjs` já roda `npm pack` (tsup a partir de `packages/<p>`, ng-packagr a partir de `dist/packages/<p>`); o CI tem um único *job* `verify`; `@cds/rte-theme` exporta `RTE_THEME_PRESETS` com os 5 presets da spec 07 (`angular`, `ocean`, `forest`, `sunset`, `monochrome`), `checkRteTheme` (72 verificações, 36 por modo), `suggestRteColor`, `createRteTheme` (37 variáveis) e `supportsRelativeColors`; `RteTheme` tem `primary`/`secondary`/`tertiary`/`mode`/`neutral`, mas **raio e densidade não**: são CSS do nível 2 (`--rte-radius`, `--rte-density`); o modo no CSS é só `color-scheme` em `.rte-root[data-rte-mode=…]`; neutros cinza só com CSS = `--rte-neutral-tint: 0`; o `examples/server-node` não tem CORS e devolve URLs relativas `/media/<nome>` (`publicPath`); GitHub Pages não permite cabeçalhos próprios (CSP só por `<meta>`).

## 1. Objetivo

Um app Angular 22 de demonstração (`apps/demo`) que mostra o editor completo, a barra e as *features* configuráveis, os 3 modos de formulário, o i18n, o envio de arquivos com progresso e cancelamento e a exibição pelo `@cds/rte-render`, mais um **playground do tema** offline que gera CSS e TypeScript que reproduzem o tema mostrado. O demo é construído e testado **como um consumidor externo**, a partir dos tarballs do `npm pack`, fora do *workspace*, provando o empacotamento no CI.

## 2. Fora de escopo

Site de documentação, referência de API, exemplos compilados do guia, README raiz e teste de 15 minutos (07c/07d, Apêndice A). **Publicação** do demo (GitHub Pages) — a 07c publica docs e demo juntos; aqui só o *build* estático como artefato do CI. Publicação no npm e Verdaccio (spec 09). Matriz Angular 22.0 × último, leitores de tela e regressão visual (spec 08; o demo fica disponível para ela). Recurso novo nos pacotes: se o demo achar defeito, a correção vai ao pacote com teste próprio e *changeset*, sem API nova sem registro no ADR 0017. Persistência do estado do playground (URL, `localStorage`). Demo em outro idioma de interface.

## 3. Decisões

## 4. API

**Nenhuma API nova nos pacotes.** Se o demo exigir correção em pacote, ela vem com teste, relatório `api/` atualizado quando tocar a superfície (Z7) e *changeset*, registrada no ADR 0017.

**Interno (fora dos pacotes):** `tools/consumer.mjs` (+ testes em `test:tools`); `apps/demo/**` (app, `serve.mjs`, `e2e/`, `public/demo-config.json`, `public/theme-check.html`, imagem de exemplo); regras novas do `check:rules` (W3, W4); *job* `demo` em `.github/workflows/ci.yml`.

## 5. Requisitos

- **R1. App e páginas (W1, W5).** `apps/demo` constrói com `ng build` no consumidor, pré-renderiza todas as rotas da W5 e hidrata sem erro; cada página faz o que a W5 descreve.
- **R2. Consumo por tarball (W2, W3).** `consumer.mjs pack prepare install build` funciona do zero num diretório fora do repositório, no Linux (CI) e no Windows (local); a prova de origem falha se um `@cds/*` vier do repositório ou com outro sha; as regras do `check:rules` têm casos positivos e negativos.
- **R3. CSP e offline (W4, R2 da spec 07).** Nenhuma violação de CSP em nenhuma página, com a política por cabeçalho **e** só pela `<meta>`; nenhuma requisição para fora da origem em nenhuma página, inclusive o playground e o envio simulado; nenhum atributo `style` no HTML pré-renderizado.
- **R4. Envio (W6).** Simulado: progresso, cancelamento (o `AbortSignal` chega ao adaptador), erro anunciado, imagem de exemplo inserida, nenhum byte do arquivo lido; servidor: com `serve.mjs --with-server`, uma imagem PNG real enviada ao `examples/server-node` aparece no editor e o arquivo existe na pasta temporária.
- **R5. Playground (W7–W9).** Presets, cores (seletor e texto), modo (com a regra do `inherit`), neutros, raio e densidade mudam a pré-visualização ao vivo; relatório com 72 verificações e sugestão; tudo operável por teclado com rótulos acessíveis.
- **R6. CSS e TS copiados (W10, W11, W13).** Textos determinísticos, só com valores fora do padrão; o CSS colado num app limpo com `theme.css` reproduz os tokens da pré-visualização; o TS compila contra os tarballs e gera o mesmo tema.
- **R7. Testes e CI (W12, W14).** Unitários verdes no consumidor; E2E J1–J7 verdes no Chromium local e nos 3 motores no *job* `demo`; artefato estático publicado pelo CI.
- **R8. Documentação.** `apps/demo/README.md` (o que é, como rodar `consumer.mjs` local e `dev` com o servidor de exemplo, aviso de que o envio simulado não envia nada); `CLAUDE.md` com os comandos do demo; ADR 0017; `docs/specs/README.md` e `07-demo-docs-exemplos.md` atualizados.

## 6. Testes

### 6.1 Unitários e ferramentas
- `test:tools` (`tools/consumer.test.mjs`): reescrita das dependências `@cds/*` para `file:`, `manifest.json` (nome, versão, sha512), prova de origem sobre um *fixture* de `node_modules` (diretório real aceito; *symlink*, caminho dentro do repositório e sha diferente recusados), escolha do diretório (`RTE_CONSUMER_DIR`, `$TMPDIR`); regras novas do `check:rules` (W3, W4) com casos positivos e negativos.
- Demo (`ng test` no consumidor): modelo do playground (padrões, presets a partir de `RTE_THEME_PRESETS`, cor inválida, limites de raio e densidade, padrões de raio/densidade iguais aos do `theme.css` instalado); gerador de CSS (só valores fora do padrão, ordem estável, modo → `color-scheme`, neutros cinza, semente inválida omitida com comentário); gerador de TS (W13: transpilar, avaliar e comparar `createRteTheme`); resumo do relatório de contraste; adaptador simulado (progresso monotônico, `abort` rejeita e para o *timer*, "falhar" rejeita com `RteUploadError`, nenhuma leitura do conteúdo do `File`).
- `consumer.mjs check-snippets` (W13) no CI.

### 6.2 Navegador real (Playwright em `apps/demo/e2e/`; local Chromium, CI nos 3 motores)
- **J1 fumaça, CSP e offline:** todas as rotas carregam sem erro de console, sem `securitypolicyviolation` (cabeçalho; e uma volta só com a `<meta>`), sem requisição fora da origem; HTML pré-renderizado sem `style=`; `axe` sem violações sérias ou críticas.
- **J2 editor completo:** digitar, negrito pela barra, item pelo menu `/`, busca abre por `Mod-F`, contador atualiza; recarregar oferece o rascunho.
- **J3 formulários:** nos 3 modos, digitar atualiza valor e validade e `rteMaxChars` mostra a mensagem formatada.
- **J4 i18n:** trocar pt-BR → en → es muda o nome acessível e os rótulos da barra sem recriar o editor.
- **J5 envio:** simulado (progresso, cancelar, falhar anunciado, imagem inserida); com `--with-server` (só Chromium), PNG real enviado ao servidor de exemplo e exibido.
- **J6 exibição:** o conteúdo do editor aparece em `[rteContent]` sanitizado (um `<script>` colado some), com o sumário `rte-toc`.
- **J7 playground:** preset muda os tokens computados da pré-visualização; relatório mostra 72 verificações; "usar sugestão" aplica a cor; reprodução do CSS na `theme-check.html` (W13); cópia pela área de transferência só verificada no Chromium (permissões), nos outros motores pelo `<pre>`.

## 7. Critérios de aceite

- [ ] `npm run check:rules` e `npm run test:tools` verdes (regras e testes novos).
- [ ] `consumer.mjs pack prepare install test build check-snippets` verde do zero fora do repositório, local (Windows) e no CI; a prova de origem acusa um `@cds/*` vindo do repositório (teste).
- [ ] J1–J7 verdes no Chromium local e nos 3 motores no *job* `demo` do CI; artefato estático do demo publicado.
- [ ] CSS copiado reproduz o tema numa página limpa (J7, 5 presets × 2 modos + tema próprio, 3 motores) e o TS copiado compila contra os tarballs e gera o mesmo tema (W13).
- [ ] Nenhuma requisição fora da origem nem violação de CSP em nenhuma página (J1).
- [ ] ADR 0017, `apps/demo/README.md`, `CLAUDE.md`, `07-demo-docs-exemplos.md` (critério "Demo consumindo os tarballs" marcado com evidência) e `docs/specs/README.md` atualizados.

## 8. Consequências

- **Spec 07 (07c/07d):** o site de docs reaproveita o `consumer.mjs` (outro app consumidor), a CSP por `<meta>`, o *job* de CI e o artefato estático do demo para publicar os dois juntos; o guia do tema aponta para o playground.
- **Spec 08:** o demo vira alvo pronto para a matriz Angular 22.0 × último (trocar as versões exatas do consumidor), leitores de tela e regressão visual; o `consumer.mjs` é a base do "app limpo".
- **Spec 09:** o mesmo fluxo de tarballs é o ensaio da publicação; trocar `file:` pelo registro real é o teste pós-publicação.
- **Pacotes:** toda mudança que quebre o consumo externo (entry, `exports`, peer, CSS publicado) passa a quebrar o *job* `demo` do PR.

## 9. Riscos

| Risco | Mitigação |
|---|---|
| Resolução de módulo escapar para o repositório (`node_modules` raiz, *symlinks* dos *workspaces*) e o demo passar sem provar o pacote | Diretório fora do repositório (W2) e prova de origem por `realpath` e sha (W3); regras do `check:rules` contra `paths`, `extends` e imports de `packages/` |
| Sem lockfile, uma dependência transitiva nova quebrar o *job* `demo` sem mudança no repositório | Dependências diretas exatas e iguais à raiz (W3); `npm ls --all` como artefato em falha (W14); a quebra é real para um consumidor novo e vira *issue* do pacote ou pino documentado no ADR 0017 |
| Duração do CI | *Job* paralelo ao `verify`; um *build* do demo para os dois modos de envio (W6); poucos E2E (W12) |
| Windows: caminho temporário, `TMPDIR` pequeno, *workers* do Firefox | `RTE_CONSUMER_DIR` explícito; local só Chromium; os 3 motores no CI |
| `<meta>` CSP diferente do cabeçalho (a `<meta>` ignora `frame-ancestors` e relatórios; o prerender emite `<script type="application/json">` do estado de transferência) | J1 roda com cabeçalho e só com `<meta>`; o JSON de estado não é executável e é permitido; documentar as diretivas que só o cabeçalho cobre |
| API da área de transferência variar entre motores no Playwright | Os testes leem o `<pre>` (fonte da verdade); a cópia real só no Chromium; *fallback* de seleção manual (W11) |
| `ng test` (Vitest/jsdom) no consumidor trazer dependências e lentidão | Versões exatas iguais às da raiz; se o *builder* falhar no consumidor, *fallback* registrado no ADR 0017: lógica pura testada com `node --test` sobre o JS transpilado pelo `tsc` do consumidor |
| Envio simulado ser confundido com envio real | Aviso visível na página e no README; nenhum byte lido (teste) |
| Peers exatos `0.0.0` e versões alteradas por *changesets* mudarem nomes de tarball | Nomes e versões lidos do `manifest.json`, nunca fixos no script |
| Defeito de pacote achado pelo demo alongar a 07b | Correção no pacote com teste e *changeset*, registrada no ADR 0017; se for grande, vira pendência com dono e o demo documenta o contorno |

## Apêndice A — Diretrizes para a 07c e a 07d (Y1–Y12)

- **Y1. Divisão.** **07c** = infraestrutura do site de docs: app `apps/docs`, *pipeline* de Markdown, navegação e busca offline, referência de API, exemplos compilados (R1), verificação de links, publicação de docs + demo no GitHub Pages e as páginas "Início rápido", "Instalação" e "Configuração" (que provam o *pipeline*). **07d** = conteúdo restante do guia (tema com a escada 0–4 e a regra do `inherit`, formulários e NG8022, barra e *features*, i18n, envio e ciclo de vida da mídia, *embeds*, segurança e modelo de ameaças, SSR, matriz de navegadores, migração, FAQ), README raiz (R5), teste de 15 minutos e fechamento da spec 07. Motivo: o guia tem ~15 seções e o teste de 15 minutos depende de pessoa externa; não cabem com a infraestrutura em 4–6 tarefas.
- **Y2. Ferramenta: app Angular 22 próprio**, pré-renderizado (`outputMode: 'static'`), construído pelo `consumer.mjs` contra os tarballs, como o demo. Rejeitados: **VitePress/Starlight/Docusaurus** (outro *framework* e outro Vite na árvore de dependências da raiz, scripts *inline* que exigem exceções de CSP, exemplos Angular só por `iframe`); **Compodoc** (documenta o fonte de projetos Angular, não os `.d.ts` publicados, e gera HTML com scripts *inline*); **TypeDoc** (reanalisa o fonte com o TypeScript 6, segunda fonte de verdade da API ao lado dos relatórios congelados). O app próprio dá CSP estrita, offline, exemplos vivos (o próprio `rte-editor`) e o mesmo pipeline já provado.
- **Y3. Markdown no *build*:** guias em `apps/docs/content/**/*.md`, convertidos por um script Node (`marked`, versão exata, licença MIT, e o `highlight.js` já presente para código) em fragmentos HTML com âncoras estáveis; inseridos por **um único** componente que usa `bypassSecurityTrustHtml` só para conteúdo gerado do repositório no *build* (regra do `check:rules` restringe `bypassSecurityTrust*` a esse arquivo). Nada de Markdown em tempo de execução.
- **Y4. Referência de API a partir do `api-extractor`:** ligar o `docModel` no `tools/api-report.mjs` gravando `.api.json` em `dist/api-model/` (não versionado; os `.api.md` continuam a verdade congelada) e gerar Markdown com `@microsoft/api-documenter` (versão exata pareada com o 7.59.4), passando pelo mesmo *pipeline* da Y3; uma página por entry (15), âncora por item, link de volta ao relatório. Um teste falha se um entry publicado não tiver página.
- **Y5. R1, exemplos compilados:** todo bloco de código TypeScript/HTML do guia vem de arquivo real em `apps/docs/examples/**` por diretiva (`<!-- example: caminho#região -->`); os componentes de exemplo são rotas do próprio site (compilados pelo `ng build` contra os tarballs, exibidos vivos) e os trechos de função pura rodam num teste. Regra do `check:rules`: bloco ` ```ts `/` ```html ` sem diretiva só com `<!-- no-compile: motivo -->`. Os *snippets* do playground (W13) entram como exemplos.
- **Y6. Busca offline:** índice gerado no *build* (JSON da mesma origem) e busca simples no cliente; nenhum serviço externo (Algolia etc.).
- **Y7. Links:** verificação no CI dos links internos e âncoras do site construído e dos READMEs; links externos só listados (verificação de rede fora do PR, informativa).
- **Y8. Publicação:** GitHub Pages por `actions/deploy-pages` no *push* para `main`, docs em `/` e demo em `/demo/` (`--base-href`), CSP pela `<meta>` (W4); `TODO-AUTOR` se o repositório/plano não permitir Pages (alternativa: só artefato).
- **Y9. Tema no guia:** a página do tema explica a escada 0–4 e a regra do `inherit` com exemplos compilados e links para o playground com o preset correspondente.
- **Y10. README raiz (R5):** início rápido (o mesmo exemplo compilado da página do site), aviso "não afiliado à Tiptap/ProseMirror", links para docs, demo e servidor de exemplo (com o aviso da R4).
- **Y11. Teste de 15 minutos:** pessoa externa, app Angular 22 limpo, pacotes por tarball enquanto não houver publicação, só a documentação; cronômetro, tropeços e correções registrados no ADR da 07d; o critério só fecha com o relato.
